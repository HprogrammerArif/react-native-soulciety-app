**Connect • Share • Grow**

It guides users through a personalized **30-day healing journey** powered by AI, provides an AI chat companion, daily mood tracking, journaling with AI insights, and a supportive community feed — all wrapped in a beautiful, calming interface.

## Overview

Soulciety is designed to be a **daily companion for emotional well-being**. The core experience revolves around a **30-day healing journey** — a personalized program generated by AI based on a user's emotional assessment. Each day unlocks new content including guided reflections, affirmations, breathing exercises, mental & physical workouts, journaling prompts, and mini-challenges.

Beyond the healing journey, users can chat with an AI companion (with text and voice modes), track their daily mood, write journal entries with AI-powered insights, and connect with a community of others on similar healing paths.

**Backend:** The app communicates with a Django REST backend hosted at `https://soulciety.cloud`. The backend handles authentication, AI content generation (via Celery background tasks), community features, and all data persistence.

## Features

### 🧘 30-Day Healing Journey
- **Personalized assessment** — 10-question onboarding that profiles the user's emotional state, coping patterns, core wounds, and healing goals
- **AI-generated daily content** — Each day includes:
  - Guided reflection
  - Affirmation
  - Mental workout with reflection prompts
  - Physical workout with instructions
  - Breathing exercise (configurable inhale/hold/exhale/rounds)
  - Mini challenge
  - Journal prompt
- **Day lifecycle** — Days unlock at midnight, content is pre-generated at 6 PM the prior day
- **Streak tracking** — Current/longest streak, milestones at days 3, 7, 14, 21, 30
- **Grace period** — Miss a day? You get until end of next day to recover your streak

### 💬 AI Chat Companion
- Text-based conversation with an AI therapist/companion
- **Voice mode** — Powered by ElevenLabs TTS for natural-sounding spoken responses
- Conversation history with pagination
- Rate-limited to 30 messages/day

### 📝 Journaling
- Create journal entries with tags and modes
- **AI-generated insights** on journal entries
- Journal archive for reviewing past entries
- Journal entries can be shared to the community

### 😊 Daily Mood Tracking
- Set your mood each day (happy, fear, sad, angry, sick)
- Mood persists locally per day and syncs to backend
- Mood selection is required before accessing the main app each day

### 👥 Community
- Create posts (text + images)
- Like, comment, follow/unfollow other users
- Tab-based filtering (All, Following, etc.)
- Share healing journey affirmations and journal entries to community
- Optimistic UI updates for instant feedback

### 🔔 Notifications
- Push notifications via `expo-notifications`
- Configurable morning and evening reminders
- Timezone-aware scheduling

### 🔐 Authentication
- Email/password registration with OTP verification
- Login with email/password
- **Google Sign-In** (via `@react-native-google-signin/google-signin`)
- **Apple Sign-In** (iOS only, via `expo-apple-authentication`)
- Forgot/reset password flow
- JWT-based authentication with access/refresh tokens

### Data Flow

1. **Screens** render UI and delegate business logic to **hooks**
2. **Hooks** use TanStack React Query to manage server state, calling **services** for API communication
3. **Services** use the configured **Axios instance** (`lib/axios.ts`) which handles auth tokens and request/response interceptors
4. **Lib modules** provide standalone utilities (auth providers, TTS, storage, AI)
5. **AsyncStorage** is used for local persistence (tokens, mood, profile cache, onboarding state)

## Core Modules Deep Dive

### 🧘 Healing Journey (`useSession` + `session.api.ts`)

The healing journey is the centerpiece of the app. Here's how it works end-to-end:

1. **Assessment** — User answers 10 questions covering emotional baseline, coping patterns, core beliefs, and healing goals
2. **Plan Generation** — Backend uses AI (Celery background task) to generate a personalized 30-day plan with 6 phases: Foundation → Awareness → Release → Rewiring → Embodiment → Integration
3. **Daily Content** — Each day's content (reflection, affirmation, workouts, breathing exercise, etc.) is pre-generated at 6 PM the day before and unlocks at midnight
4. **Session Flow** — Users go through an 8-step session each day:
   - `SessionIntro` → `Session_1` (Reflection) → `Session_2` (Affirmation) → `Session_3` (Mental Workout) → `Session_4` (Physical Workout) → `Session_5` (Breathing) → `Session_6` (Challenge) → `Session_7` (Journal) → `Session_8` (Complete)
5. **Completion** — Marking a day complete updates the streak, checks for milestones, and can include mood + journal entry
6. **Progress Tracking** — Streak, milestones, grace period, total days completed

**Key Query Keys:**
```typescript
["healing-today"]          // Current day's content
["healing-today-state"]    // Journey state (no_plan, generating, available, etc.)
["healing-plan"]           // Full 30-day grid
["healing-progress"]       // Streak & progress data
["assessment-questions"]   // Assessment question set
["saved-affirmations"]     // User's saved affirmations
```

### 💬 AI Chat (`chat.tsx` + Chat components)

- Conversations are managed server-side with CRUD operations
- Messages support markdown rendering via `MarkdownText.tsx`
- Voice mode uses `VoiceModeModal.tsx` with ElevenLabs TTS
- Pagination for message history (20 per page)
- Rate limited: 30 messages/day

### 👥 Community (`useCommunity.ts`)

The community hook implements **full optimistic updates** for:
- Creating posts (text content appears instantly, image updates after server response)
- Liking/unliking posts
- Following/unfollowing users
- Editing and deleting posts

All mutations use the `onMutate` → `onError` (rollback) → `onSettled` (revalidate) pattern.

### 📝 Journaling (`useJournal.ts`)

- Simple CRUD with React Query
- Entries include: content, mode, tag, AI-generated insight
- Supports creation from both the journal screen and within healing sessions

## API Integration

### Base Configuration

The API client is configured in [`lib/axios.ts`](lib/axios.ts):

```typescript
// Base URL from app.json → expo.extra.BACKEND_URL
baseURL: "https://soulciety.cloud"

```

### Request Interceptor
- Automatically attaches `Authorization: Bearer <token>` from AsyncStorage
- Logs all outgoing requests (method, URL, payload presence)

### Response Interceptor
- Logs all responses (status, size)
- **401 handling:** Clears access token, prevents redirect loops
- **403/404:** Warning-level logging
- **5xx:** Error-level logging
- Network errors logged with code and URL

## State Management

### Server State — TanStack React Query

All server data is managed through React Query with these patterns:

```typescript
// Queries (read operations)
useQuery({
  queryKey: ["unique-key"],
  queryFn: apiFetchFunction,
  staleTime: 30_000,        // How long data is considered "fresh"
  gcTime: 5 * 60 * 1000,    // How long unused data stays in cache
});

// Mutations (write operations)
useMutation({
  mutationFn: apiWriteFunction,
  onSuccess: () => {
    queryClient.invalidateQueries({ queryKey: ["affected-key"] });
  },
});
```

**Cache Configuration Patterns:**
| Data Type | `staleTime` | `gcTime` | Rationale |
|---|---|---|---|
| Assessment Questions | 5 min | 10 min | Rarely changes |
| Today's Healing Content | 30 sec | 5 min | May change state during the day |
| Healing Plan | 1 min | 10 min | Stable once generated |
| Progress/Streak | 30 sec | 10 min | Updates on day completion |
| Profile | ∞ (Infinity) | ∞ | Only changes on explicit update |

### Client State — AsyncStorage

Local persistence is used for:

| Key | Purpose | Module |
|---|---|---|
| `accessToken` | JWT access token | `useUser` |
| `refreshToken` | JWT refresh token | `useUser` |
| `profile` | Cached user profile | `profileStorage.ts` |
| `user_mood` | Today's mood (`{ moodKey, date }`) | `useMood` |
| `onboarding` | Whether onboarding is complete | `app/index.tsx` |

## AI & Voice Integration

### ElevenLabs Text-to-Speech (`lib/elevenlabsTTS.ts`)

The app uses ElevenLabs for high-quality voice synthesis:

- **Model:** `eleven_multilingual_v2`
- **Voice ID:** `pjcYQlDFKMbcOUp6F5GD`
- **Queue-based playback:** Text is split into sentences, fetched in parallel, and played sequentially
- **Prefetching:** The next 2 segments are always pre-fetched during playback
- **Memory management:** Sounds are unloaded immediately after playback

```typescript
import { speak, stop } from '@/lib/elevenlabsTTS';

// Start speaking
await speak("Your guided reflection text...", {
  onStart: () => console.log("Speaking started"),
  onDone: () => console.log("Speaking complete"),
  onError: (err) => console.error(err),
});

// Stop speaking
```

### Flow Overview

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  Signup  │───►│   OTP    │───►│  Login   │───►│ Profile  │
│  (email) │    │  Verify  │    │          │    │  Fetch   │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
                                     │
                    ┌────────────────┤
                    │                │
              ┌──────────┐    ┌──────────┐
              │  Google  │    │  Apple   │
              │ Sign-In  │    │ Sign-In  │
              └──────────┘    └──────────┘
```

### Token Management

- **Access token** stored in AsyncStorage as `accessToken`
- **Refresh token** stored as `refreshToken`
- Tokens are automatically attached to requests via Axios interceptor
- On 401 response, access token is cleared and user is redirected to login

### Social Login

Both Google and Apple social logins send `{ email, full_name, image }` to the backend, which returns the same `AuthResponse` (access + refresh tokens) as email/password login.

## Best Practices

### Code Organization

1. **Screens are thin** — Screens should primarily compose components and delegate logic to hooks. Avoid putting API calls or complex state management directly in screen files.

2. **One hook per domain** — Each feature domain has its own hook (`useUser`, `useMood`, `useSession`, `useCommunity`, `useJournal`) that encapsulates all queries, mutations, and derived state.

3. **Services are pure functions** — API service files export pure async functions that take payloads and return typed responses. No hooks, no side effects.

4. **Components follow module pattern** — Feature-specific components live in `components/modules/<Feature>/`. Shared components go in `components/global/`.

### TypeScript

1. **Strict mode is enabled** — All code must pass strict type checking
2. **Define types in services or `types/`** — API response types are co-located with their service functions in `session.api.ts`, or in `types/` for shared types
3. **Use path aliases** — Import with `@/` prefix instead of relative paths:
   ```typescript
   import { useUser } from "@/hooks/useUser";   // ✅
   import { useUser } from "../../../hooks/useUser";  // ❌
   ```

### React Query

1. **Use appropriate stale times** — Don't over-fetch. Assessment questions rarely change (5 min stale), but today's content may update (30 sec stale).

2. **Invalidate on mutations** — Always invalidate related queries after mutations:
   ```typescript
   onSuccess: () => {
     queryClient.invalidateQueries({ queryKey: ["affected-data"] });
   }
   ```

3. **Optimistic updates for UX** — Use the `onMutate` → `onError` → `onSettled` pattern for instant feedback (see `useCommunity.ts` for examples).

4. **Disable unnecessary refetches** — Most queries have `refetchOnWindowFocus: false` to prevent excessive API calls on mobile.

### Authentication

1. **Never store tokens in memory only** — Always persist to AsyncStorage for session survival across app restarts.
2. **Clear all user data on logout** — Remove tokens, clear profile cache, remove React Query data.
3. **Handle 401 gracefully** — The Axios interceptor handles this automatically.

### Performance

1. **Use `expo-image` over `<Image>`** — Better caching and performance for remote images
2. **Unload audio after playback** — The TTS module unloads Sound objects immediately after they finish playing
3. **Limit re-renders** — Use `staleTime: Infinity` for data that shouldn't trigger re-fetches (like cached profile)
4. **Prefetch content** — The TTS system prefetches the next 2 audio segments during playback

### Security

> ⚠️ **Critical Security Concerns:**

1. **Never commit `.env` files** — The `.env` file is gitignored, but ensure sensitive keys stay out of version control
2. **API keys in source code** — The `elevenlabsTTS.ts` and `gemini.ts` files contain API keys inline. These should be moved to environment variables or a secrets manager:
   ```typescript
   // ❌ Current (insecure)
   const ELEVENLABS_API_KEY = "sk_f14b09...";
   
   // ✅ Better
   const ELEVENLABS_API_KEY = process.env.EXPO_PUBLIC_ELEVENLABS_API_KEY;
   ```
3. **`credentials.json` should be gitignored** — This file contains Android keystore passwords and should not be in version control
4. **`C.md` should be removed** — Contains plaintext credentials that should never be committed

## Troubleshooting

### Common Issues

#### Metro bundler cache issues
```bash
npx expo start --clear
```

#### NativeWind styles not applying
1. Ensure `global.css` imports are present in `_layout.tsx`
2. Clear Metro cache: `npx expo start --clear`
3. Check that the file is in the `content` array in `tailwind.config.js`

#### Google Sign-In not working
- Google Sign-In requires a **development build**, not Expo Go
- Verify `google-services.json` has the correct `client_id` (type 3 = web client)
- Ensure the SHA-1 fingerprint matches your build

#### Apple Sign-In fails
- Only works on **iOS physical devices** (not simulator in most cases)
- Requires Apple Developer membership
- Check `appleTeamId` in `app.json`

#### 401 errors on API calls
1. Check if `accessToken` exists in AsyncStorage
2. Verify token hasn't expired
3. The interceptor auto-clears invalid tokens — user may need to re-login

#### Build fails with EAS
```bash
# Check EAS CLI version
eas --version   # Should be ≥ 18.0.3

# Login to EAS
eas login

# Check project configuration
eas diagnostics
```

#### Audio/TTS not playing
1. Ensure device is not in silent mode (iOS)
2. The TTS module sets `playsInSilentModeIOS: true`, but the device volume must be up
3. Check ElevenLabs API key validity and rate limits

## Contributing

### Development Workflow

1. Create a feature branch from `main`
2. Follow the established patterns:
   - New screen → `app/` directory
   - New hook → `hooks/` directory
   - New API function → `services/` directory
   - New component → `components/modules/<Feature>/`

5. Test on both iOS and Android when possible

1. **Define types** in `types/` or co-locate with the service
2. **Create API service functions** in `services/`
3. **Create a custom hook** in `hooks/` using React Query

5. **Create the screen** in `app/`
6. **Update navigation** if adding new routes
